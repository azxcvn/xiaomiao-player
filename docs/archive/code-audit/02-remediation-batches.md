## 0. 怎么用这份文档

### 0.1 每个批次的固定结构

1. **包含条目** —— 报告中的编号 + 一句话
2. **为什么这么捆** —— 不捆会返工的具体理由
3. **验收什么** —— 你在真机上要亲眼确认的行为（这是本批次「结题」的唯一标准）
4. **连带影响** —— 修完这批，后面哪几条的**表现**会变（不是内容变）
5. **风险等级** —— 低 / 中 / 高（高风险批次建议单独验，别和其他批次混在同一次安装里）

### 0.2 铁律：一批一验，验完再开下一批

- 每批修完 → 我跑静态分析 + 测试（按你的规则 2，我不编译）→ **你在 Android Studio 连真机编译验证** → 通过后才开下一批。
- **不要攒着一起验**。体检里有多条「同一症状、多个根因」（见 §1），攒着验会导致「修了 3 条症状还在」，你无法判断是哪条没修好。
- 若某批验收不通过：**先停下反馈**，不要继续下一批——后面的批次有 5 组依赖前面的行为（§1）。

### 0.3 关于「代码修完再补测试」

体检报告里「补测」相关条目（弹幕控制器/进度服务/文件操作/指纹/扫描器 5 个盲区）**必须排在对应修复之后**。理由：现在补测等于把**当前错误行为**锁进断言（尤其是删除语义、弹幕合并计数、缩略图 LRU 语义这三处），后续修完测试会「通过但语义已变」，反而误导。

| # | 约束 | 违反的后果 |
|---|---|---|

## 2.2 【真机追加 · 2026-09】B5.5 ｜ 同名字幕重复挂载止血（**✅ 已完成 · 真机复验通过**）

> 触发：真机播放「`字幕测试.mp4` + 同目录同名 `字幕测试.ass`」时，字幕面板出现**两条完全相同的轨道**
> （都显示 `ass · 外挂 · ASS`、都带垃圾桶删除按钮）；点轨道时高亮乱跳、界面闪烁。

**包含条目**
- **P1-41（本批只做根因这一半）**：同一个外挂字幕文件被**挂载两次** ——
  ① mpv 自带的「同名外挂字幕自动加载」会自动挂一条（全仓含 media_kit 都**没有**设置 `sub-auto`，
  用的是 mpv 编译默认：与视频同名即自动加载）；② `_autoLoadSameNameSubtitle` 又 `sub-add` 同一条。
  - **决定性证据（用户真机实验）**：字幕名加 `-SC`/`-TC` 后缀后，mpv 的"同名"匹配失效 → 只剩 App 挂的
    一条 → 上述症状**全部消失**；字幕名与视频名完全相同时必现。
- 🚧 **本批不做（留给 B5）**：切轨 `sub-reload` 引发的异步重建（P1-41 后半）+「关闭字幕」条件行位移（P2-42）。

**做了什么（应用侧，1 个文件 1 处改动）**

`lib/services/subtitle_service.dart` 的 `applyOnInit()` **首行**（必须在任何 `await` 之前 ——
`sub-auto` 只在文件加载时生效，首次 open 之后再写就无效）：

```dart
unawaited(native.setProperty('sub-auto', 'no').catchError((_) {}));
```

即**外挂字幕来源唯一化**：mpv 不再自动加载同名文件，同名自动加载一律由 App 负责（App 匹配更准：
简繁 `-sc/-tc` 优先 + 记忆路径 + 只认字幕扩展名）。时序已核对：`applyOnInit()` 在 `player_page.dart`
的 `initState` 调用、首次 `open` 在其后，该写入是第一个 `await` 之前发出去的，先于 open 到达 mpv。

**代价（已拍板接受，见 §5.1 D9）**：失去 mpv 原生的同名匹配能力（把字幕放在 `sub/` 子目录、
mpv 的 `--sub-file-paths` 场景）。App 的匹配只扫视频所在目录；日后若确实需要，在 B5 补「App 侧子目录查找」。

**✅ 真机复验（2026-09，用户实测）**
1. ✅ 字幕面板**只剩一条**外挂轨（不再出现两条一模一样的 `ass · 外挂 · ASS`）。
2. ✅ 点轨道：选中高亮稳定、底部「关闭字幕」正常出现；再点取消选中；无「点了没反应 / 高亮乱跳」。
3. ✅ `字幕测试-SC.ass` / `-TC.ass` 那组照常自动加载（简体优先）且只有一条。
4. ✅ 手动「导入外部字幕」恰好新增一条；退出重进视频，上次选中的字幕轨仍能恢复。
5. ❌ **残留**：极快反复点击**外挂**轨（自动导入 / 手动导入）时，仍能看到「导入外部字幕」瞬时窜到
   「关闭字幕」那一格 —— 已判定为**另一个缺陷**，归 B5 的 P1-41 后半 + P2-42。
   ⚠️ 纯内嵌字幕轨之间反复切换**不会**出现 → 这是判据：闪烁只与外挂轨的重挂有关。

**仍存在的缺陷（并入 B5，不在本批）**

**实现中发现（原清单之外、动手时才看清的）**

1. **「测试连接」不能跟着浏览路径一起重试**：接到 `retry_policy` 后，一次 12 秒超时会变成
   `12s + 退避 + 12s + 退避 + 12s ≈ 37s`，验收 2 的「12 秒内报超时」直接不成立。分级超时的意义是
   让用户尽快看到结论 → 自检路径固定 `RetryPolicy.none`，只有浏览类操作重试。
2. **`Socket.connect(timeout:)` 超时抛的是 `SocketException("Connection timed out")`**，不是
   `TimeoutException`——只 catch `TimeoutException` 会漏掉黑洞地址最常见的那条路径（已一并处理）。
3. **D7 不能只看 `OPTS UTF8 ON` 的应答**：很多服务器只是**没实现**这个命令（回 500）但实际就是
   UTF-8，照「不支持 → GBK」写死会把现在好用的服务器改成乱码。落地为「先按**严格** UTF-8 试解列表，
   解不通才判定 GBK」——既修好老 IIS/Serv-U，又不回归。
4. **背压窗口的算法不能随便写**：最初想用「全局许可数（信号量）」，但待输出块的属主可能正好在等
   许可 → 死锁（持有许可的块全在等它）。改成「离下一个待输出块的距离」这个**单调窗口**后，
   待输出块的属主恒在窗口内，前进性由构造保证；单测里专门跑「暂停 → 恢复 → 必须读完」。
5. **`StreamController` 的 paused 不会拦生产者**：`add` 在暂停的订阅上照样缓冲，只靠
   「在途块数上限」并不能防「消费者不读时整文件进内存」→ 必须同时用 `onPause`/`onResume` 停手。
6. **fork 侧「恢复 checkStatus」只恢复到读路径**：体检报告的完整建议是把 0.0.9 里被整段注释掉的
   `_checkStatus` 恢复，但那会改变**所有命令**的错误语义（超出本批必要范围）→ 只让读路径把错误状态
   抛出来（其余保持与上游一致），并在 `FORK.md` §7 写明这是**有意不做**。
7. **解码失败选择「断开连接」而不是「尝试重新对齐帧」**：帧内游标位置已经不可知，静默错位比断连
   危险得多（错位 = 此后所有请求静默拿到错误数据）。同样写进 `FORK.md` §7。
8. **`RandomAccessFile.read(count)` 旧实现无论读到多少都返回整个 count 长度**：到末尾会把一整块
   零字节当数据交出去（上层拿到静默损坏的数据）→ 一并改成只返回真正读到的字节。
9. **报告 §3 第 20~23 条（FTP `isConnected()` 恒真、PROPFIND 响应体无上限、网络浏览页无会话号、
   代理 `_ensureServer` 无在飞去重）不在 B10 条目清单内**，按「禁止顺手修复」**未动**，已在体检报告
   对应条目标注 ⏳（其中第 20 条被本批的「死连接作废重连」**部分缓解**，但
   `NetworkClient.isConnected()` 仍可能说谎）。
10. **改动涉及 `pubspec.yaml`**：新增直接依赖 `charset` 与 fork 版本号 `0.0.9-mk.2` 都改了
    `pubspec.lock` → 用户侧 build 前需 `flutter pub get`（Android Studio 会自动做）。

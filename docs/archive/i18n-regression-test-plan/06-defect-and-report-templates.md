# 06 · 缺陷与汇报模板

> 所有输出都用这里的模板，**不要自由发挥结构** —— 用户要靠固定格式快速比对多轮结果。
> 编号规则：
> - 用例 ID：`T<阶段号>-<域代号>-<三位序号>`（例：`T3-PLR-007`）
> - 缺陷 ID：`DEF-<阶段号>-<两位序号>`（例：`DEF-3-02`）
> - 未验证 ID：`NV-<用例ID>`（例：`NV-T5-NET-004`）
>
> 域代号：`SYS`(系统/原生) `HOME`(首页与媒体库) `PLR`(播放器) `SUB`(字幕) `DMK`(弹幕)
> `NET`(网络存储) `CAST`(投屏) `BILI`(哔哩哔哩) `DL`(下载) `SET`(设置与外观) `I18N`(多语言专项) `REG`(静态回归)

---

## 1. 缺陷单模板（发现即写，不要攒）

```markdown
### DEF-<阶段>-<序号> · <一句话标题> · P<0/1/2/3>

- **用例**：T<阶段>-<域>-<序号>（若为走查发现、无对应用例，写「走查发现」）
- **语言**：简体中文 / English / 两种都是
- **环境**：commit `<短号>` · debug/release · 系统语言 `zh-Hans-CN` · 设备 emulator-5554
- **前置**：<素材 ID、页面、设置状态>
- **复现步骤**（可照做，越小越好）：
  1. …
  2. …
  3. …
- **实际结果**：<现象，带具体数值/文案>
- **期望结果**：<应为什么样；若为「改造前是这样」请附证据>
- **证据**：`_evidence/阶段N/T3-PLR-007_1.png`、`_evidence/阶段N/T3-PLR-007_logcat.txt`
- **是否回归**：是（改造引起）/ 否（改造前就有，证据：…）/ 未确认
- **日志**：
  ```
  <logcat 关键行，10 行以内>
  ```
- **处理**：已修（改了 `<文件:行>`，验证：…）/ 仅登记 / 待用户拍板
```

**写缺陷的纪律**：

- 「实际结果」必须能被别人复现；写清具体文案/数字/页面，不要写「有些地方不对」。
- 判定「是否回归」时优先用 `git show 7276793^:<文件>` 看改造前原样；判不了就写「未确认」，别猜。
- 一条缺陷只写一件事；同类多处合并成一条并列位置。

## 2. 未验证项模板（素材缺失 / 环境不可达 / 需要用户配合）

```markdown
### NV-T<阶段>-<域>-<序号> · <用例标题>

- **状态**：未验证
- **原因类别**：缺素材（<Mxx>）/ 环境不可达 / 需用户配合 / 会破坏数据（待授权）
- **补齐后能否补测**：能（补 <Mxx> 即可）/ 不能（说明为什么）
- **已做的部分**（如果有）：<做了哪些步骤、看到什么>
```

## 3. 阶段报告模板（每阶段收口必须按此输出）

```
## 阶段 <N> · <阶段名> 完成情况

### 1. 结论
- 本阶段用例：<总数> 条；通过 <n>；不通过 <n>；未验证 <n>；部分验证 <n>

### 2. 环境

- 素材到位情况：<Mxx 已备 / 缺哪些>

- T4 residual 三口径：<0 / 0 / 0；白名单过期 0>
- T5 用例：<逐条已勾选>
- T6 证据：<_evidence/阶段N/ 下文件数>

### 4. 缺陷（本阶段新增）
```

## 4. 最终总报告模板（全部阶段结束后）

```markdown
# 多语言改造 · 全量回归测试报告

## 一、总体结论
- 被测对象：commit `<短号>`（<分支>），包 `<versionName>+<versionCode>`，<debug/release>
- 覆盖：<阶段数> 个阶段、<用例总数> 条用例；通过 <n> / 不通过 <n> / 未验证 <n>
- **原有功能是否受多语言改造影响**：<明确回答；若有影响，列出影响面>
- **多语言本身是否达标**：<双语可用性、残留、溢出、插值/复数的结论>

## 二、证据与门禁
- analyze / test / residual 三口径 / ARB 对称性 的最终数字
- 证据目录：`_evidence/`（按阶段，<文件数> 个）

## 三、缺陷汇总（按级别）
| ID | 标题 | 级别 | 回归? | 状态 | 是否已修 |
|---|---|---|---|---|---|

## 四、未验证汇总（按原因）
| 原因（素材 ID / 环境） | 涉及用例数 | 补齐后能否补测 |
|---|---|---|

## 五、明确「不受影响」的部分（给用户吃定心丸）
- <按功能域列出：哪些域做了哪些用例、结论是「与改造前一致」>

## 六、仍然不确定 / 建议人工再看的
- <逐条写，不要藏>
```

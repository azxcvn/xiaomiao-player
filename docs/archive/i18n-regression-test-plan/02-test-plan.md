# 02 · 测试方案

> 目的：在「接入官方 l10n 多语言」之后，**验证原有功能有没有被这轮改造影响**，同时验证多语言本身是否达标。
> 本文件说「测什么、怎么测、分几个阶段、每阶段什么算过」；具体逐条步骤在 `03-test-case-list.md`。

## 0. 目标与非目标

### 0.1 目标

| # | 目标 | 判定口径 |
|---|---|---|
| G-1 | **回归**：原有功能行为未被改造破坏 | 中文界面下，行为与文字与改造前（`7276793^`）逐项一致；关键路径可用旧包（M18）对照 |
| G-2 | **多语言达标**：中英双语都能正常用 | 英文界面无中文残留（除 `04-data-baseline.md` §4.2 清单）、无溢出/截断、插值完整、复数正确、切换即时、可持久化 |
| G-3 | **改造遗留项收口**：迁移期间没条件验证的部分 | Android 原生侧 4 项、通知渠道、长文两版、通知/后台播放、崩溃提示（见 `07-open-items-and-todo.md` §1） |
| G-4 | **静态与自动化门禁仍绿** | `flutter analyze` / 全量 `flutter test` / `residual` 三种口径 |
| G-5 | **给出可信结论**：哪些域确认不受影响、哪些有缺陷、哪些没测到 | `06-defect-and-report-templates.md` §4 的总报告 |

### 0.2 非目标（本轮**不测**，别浪费时间）

- 性能/功耗/内存基准测试、启动耗时对比。
- 真机机型兼容性矩阵（只有 MuMu 模拟器；真机由用户自己看）。
- iOS / Windows / macOS / Web 目标（本工程只有 Android）。
- 代码审计、GPL 合规、依赖漏洞扫描。
- 第三方服务本身的可用性（B 站接口挂了不是本项目缺陷）。
- 新功能开发、UI 重设计、文案润色。
- 改造**前**就存在的老问题的修复（只登记，见 `01-execution-protocol.md` §1.3）。

## 2. 为什么必须做这轮测试（改造面不只是文案）

虽然改造的**目的**是文案，但为了「文案能在正确的地方取到」，动了很多**结构性**东西。
开工前已用只读扫描得到：**481 个功能点**（`tools/_scan_features.md`）+ **29 条回归风险（高 2 / 中 6 / 低 21）、11 条结构性隐患与 2 处确认的中文残留**（`tools/_scan_regression.md`）。
这些结论已转成 `03-test-case-list.md` 附录 B 的 20 条定向核查用例，并登记在 `07-open-items-and-todo.md` §1.1（R1–R19）。
以下是本轮回归的**风险来源**（按类别）：

| # | 结构性改动 | 为什么可能出事 | 重点验证 |
|---|---|---|---|
| 1 | **异常体系替换**：`ArgumentError` → `NetworkPathException`；`StateError`/`FileSystemException` → `CastException`/`LanMediaServerException` | 上层 `catch` 的类型判断可能不再命中，异常可能穿透或静默 | 网络路径非法、投屏设备离线、局域网服务文件缺失时的提示 |
| 2 | **错误管道类型变化**：`LoadError.message`、`CommonListController.error` 由 `String` → `Object`；`DanmakuServerSearchOutcome.error` → `Object?` | 三态渲染/刷新失败保留旧数据/加载更多的分支可能显示空或崩 | 各列表页的网络失败态、空态、加载更多 |
| 3 | **回调签名变化**：`onAudioFallback` 第三参改枚举、`onNetworkDanmakuLoaded` 由一句拼好的字符串改成四参 | 调用点漏改 → 提示缺失或参数错位 | 不可播放音轨自动回退提示、网络弹幕加载回执 |
| 4 | **model 字段删除**：`EqualizerPreset.label`、`BiliUser.vipLabel`、`SubtitleEntry/WyzieSubtitle.displayName/displayLanguage`、`BiliCoverSize.label`、`FolderFilterMode.label/subtitle`、`wyzieFallbackSources['all']` | 死字段被删；若有漏改的读取点会编译不过（能兜住），但要确认**显示内容没变** | 均衡器预设名、B 站会员标识、在线字幕条目名/语言、封面尺寸选项、文件夹过滤模式、字幕来源「全部」 |
| 5 | **持久化字段变化**：下载任务新增 `errorCode`/`errorArgs`；弹幕搜索错误改 `errorKind` | **跨版本读旧数据**可能解析失败（老用户升级场景） | 升级安装后：已有下载任务、搜索历史、设置项是否还在 |
| 6 | **工具函数搬迁/语义化**：`dolby_vision_hint` 从 `utils/` → `widgets/`；播放诊断三个含中文的格式化函数移到 `label_maps`；`danmaku_timeline` 偏移格式化改 ASCII + UI 映射；`custom_subtitle_parser` 的 `sourceLabel` 由「自定义」→ `custom`；`build_info_service.copyHint()` 改枚举；`CacheCategory` 只留 `key` | 搬迁后行为等价性、映射是否漏分支 | 杜比视界提示、播放诊断面板、弹幕时间轴偏移显示、字幕来源标签、关于页复制提示、缓存管理类别名 |
| 7 | **文案拼接与格式**：全角标点改半角（`、`→`, `、`：`→`: `）、单位与秒数拼接、占位符类型（`commonSecondsValue` 是 `int`、`playerDelaySeconds` 是 `String`，两者**故意不合并**） | 拼接错位、参数丢失、类型不匹配（迁移中就踩过一次：字幕延迟面板秒数） | 文件传输进度、缓存清除弹窗、删除确认、字幕延迟面板、诊断长句 |
| 8 | **Android 原生**：Kotlin 硬编码改 `getString`、`AndroidManifest` 的 `label` 改 `@string/app_name`、新增 `values/` 与 `values-en/` | **从未编译验证过** | 应用名、通知渠道名/描述/标题/正文、存储卷回退名、崩溃提示 Toast |
| 9 | **`const` 移除与取值时机**：为了能取 l10n，多处去掉 `const`、把取值从 `initState`/静态缓存挪到 `build`/`didChangeDependencies` | 取值时机不对 → **切语言后个别界面不刷新**，或 `initState` 里查 `InheritedWidget` 导致页面永远 loading | 切换语言后逐页检查；所有带输入框初值的面板（字幕延迟） |

**因此本轮不能只「跑一遍看看」**：每个域至少要走「中文主路径 + 英文同路径 + 切换即时性」三件事。

## 5. 判定准则

### 5.1 回归判定（中文侧）

1. **行为一致**：同一操作的结果与改造前一致（可对比旧包 M18 或 `git show 7276793^:<file>` 看改造前源码/文案）。
2. **文字一致**：中文界面文字必须与改造前**逐字一致**（迁移时承诺「zh 逐字不变」）。
3. **不是「能跑就行」**：只看主路径不够，必须覆盖每个域的**错误分支**（无网络、文件不存在、设备离线、非法输入）。

### 5.2 多语言判定（英文侧）

| 项 | 标准 |
|---|---|
| 残留 | 除 `04-data-baseline.md` §4.2 清单外，界面不应出现中文 |
| 溢出 | 文案不截断、不压盖、不换行错位（重点：外观页网格、胶囊导航、面板标题、诊断长句、按钮） |
| 插值 | 参数必须出现且位置正确（文件名、数量、大小、速度、错误原因） |
| 复数 | 任何「N 个/项/文件」在 1 与 2 时形式正确 |
| 即时性 | 切换语言后**不重启**当前页立刻变；返回上一页仍一致 |
| 持久化 | 杀进程重开保持；非法值回落中文 |

### 5.3 「设计如此」清单

`04-data-baseline.md` §4.2 的 14 条（日志中文、截图文件名、相册名、第三方内容、角标匹配键、默认服务器持久化名、原生资源跟随系统语言…）**不算缺陷**；撞上时按 `06-defect-and-report-templates.md` §5 记一条「非缺陷说明」。

### 5.4 证据门槛

- 每个**断言点**一张截图（不是只在用例结尾截一张）；失败/异常额外附 logcat。
- 截图与用例 ID 对应，落在 `_evidence/stageN/`。
- 没有证据的结论 = 未验证（不许写「已通过」）。

## 6. 执行顺序与优先级

1. **P0 冒烟**（每阶段开工先跑）：装包 → 启动 → 首页 → 我的 → 进播放页 → 返回 → 不崩不卡 → logcat 无 Flutter 异常。
2. **P1 主路径**：该阶段功能域的正常流程。
3. **P2 错误与边界**：无网络、文件不存在、权限拒绝、非法输入、超大/超小值、空数据。
4. **P3 观感**：英文溢出、对齐、标点、动画（AI 截图标注 → 交用户判）。

阶段内部按 P0→P3 顺序做；**P0 不过不用继续**。

## 7. 风险与应对

| 风险 | 表现 | 应对 |
|---|---|---|
| 素材不足 | 网络存储/投屏/B 站/字幕源不可测 | 按 `01-execution-protocol.md` §5 记未验证 + 汇总缺口；先做不依赖素材的域 |
| 网络不稳/被墙 | B 站、GitHub、弹弹Play 时好时坏 | 同一用例失败重试 2 次；仍失败则记「环境不可达」而非缺陷；附证据 |
| 模拟器 ≠ 真机 | 解码能力、性能、Houdini 翻译层差异 | 结论里注明「仅代表模拟器」；真机项交用户 |
| 坐标点不准 | 点击没反应/点错 | 每步先截图确认界面，再按截图像素算坐标（×1.4985）；不确定就先截一张 |
| 无法文本断言 | Flutter 不上报语义树 | 以截图为准；必要时对照 ARB 键值（`04-data-baseline.md` §4.1）判断文案是否为预期 |
| 改造前老问题混入 | 误报回归 | 用 `git show 7276793^:<file>` 或旧包（M18）确认；判不了就写「未确认」 |
| 误把「设计如此」当缺陷 | 报告噪音 | 先查 `04-data-baseline.md` §4.2 |
| 改动污染基线 | 修 bug 后旧结论失效 | 每次改代码：登记改了哪些文件 + 重跑相关用例 + 在报告里写明「基线 commit 已变为 X」 |
| 测试期间 App 数据被清 | 通知渠道名、设置项丢失 | 清数据前先记录当前设置态；只在需要验证「全新安装」时做，且需授权（M19） |

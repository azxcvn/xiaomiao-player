# 03 · 测试用例清单（逐条勾选）

> 用法：**一条用例一个闭环**（见 `01-执行协议.md` §2）。做完把 `- [ ]` 改成 `- [x]`，并在行尾追加 `｜结果：…`。
> 行格式：`- [ ] ID · 用例名 ·P<优先级>· — 步骤 ｜ 预期 ｜ 素材 ｜ 自动化 ｜ 结果`
> - **ID**：`T<阶段>-<域>-<序号>`；域代号：`SYS`(基线/系统) `HOME`(首页媒体库) `PLR`(播放器) `SUB`(字幕) `DMK`(弹幕) `NET`(网络存储) `CAST`(投屏) `BILI`(哔哩哔哩) `DL`(下载) `SET`(设置外观) `I18N`(多语言) `REG`(静态回归)
> - **优先级**：P0 冒烟阻断 / P1 主路径 / P2 边界与错误 / P3 观感
> - **素材**：`05-素材需求清单.md` 的编号；`—` 表示不需要
> - **自动化**：`可`（adb 能独立完成）/ `部分`（需要素材或人工判图）/ `不可`（必须用户真机或人眼）
> - **结果**写：`通过` / `不通过（DEF-x-y）` / `未验证（缺 Mxx）` / `部分验证` / `非缺陷（见 04 §4.2 第 n 条）`，并附证据文件名。
>
> **每阶段开工先跑 P0 冒烟**，不过就别往下做。

> **本清单与功能点总表的关系**：`tools/_scan_features.md` 是**穷尽功能点总表（481 条，带入口路径/文件/可测性判定）**；本清单是它的**可执行子集**（含步骤与证据要求）。
> 正文（阶段 0–7）覆盖主路径与高风险点，**附录 A 是补齐缺口**的补充用例。走查类用例（`T7-I18N-*`）请**配合扫描表逐域核对**，确保每个功能点都被某个用例覆盖到。
> 扫描表还给出了「已确认不存在/未接入的功能」（其 §13，避免凭空造用例）与「已有测试覆盖缺口」（其 §14.4，10 个完全没测试覆盖的域）——补充 L1 自动化测试时以 §14.4 为清单。

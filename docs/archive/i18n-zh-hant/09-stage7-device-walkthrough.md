## 2. 怎么执行

1. AI 先把 §3 表格打印给用户（或让用户直接看本文件）；
2. 用户按用例逐条在真机上做，回复"通过 / 不通过 / 复现步骤 / 截图"；
3. AI 把结论写进表格的「结果」列，不通过的开缺陷条目（§5 模板）；
4. 缺陷修完 → 用户复验 → 结论改成"通过（复验）"；
5. 全部有结论后写收口报告（§6）。

> 走查素材准备：一份**繁体字幕**视频、一份**简体字幕**视频（验数据层不受影响）、一个**长文件夹名/长弹性文件名**（验溢出）、一个网络源（FTP/WebDAV 任一）。

## 5. 收口报告（阶段 7 结束时写）

**收口报告就写在本目录**：`杂项文件\繁体中文接入方案\收口报告.md`（本目录不进 Git）。
**归档时机**：等用户下命令后，再把整包移到 `docs/archive/i18n-zh-hant/` —— 这一步**不许自己动**。

报告必须包含：

1. 用例统计：总条数 / 通过 / 不通过 / 未验证（未验证要写原因）；
2. 缺陷清单：编号、状态、修改文件；
3. 最终门禁复跑结果：G1–G5 的实际输出结论 + 通过数；
4. 改动文件全清单（含新增/删除）；
5. **没做与没验到的**（如实写）；
6. 提交建议（标题 + 正文要点），**等用户说"提交"再动手**。

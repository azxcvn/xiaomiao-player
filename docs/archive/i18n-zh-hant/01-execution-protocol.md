# 01 · 执行协议（AI 执行者必读）

> 本协议继承仓库根 `AGENTS.md` 与第一轮 `docs/archive/i18n-migration-plan/01-execution-protocol.md` 的纪律，只保留本轮仍然适用的部分，并补本轮专属条款。

---

## 1. 红线（违反任一条 = 立即停下报告）

1. **禁止编译与运行**：不 `flutter build`、不 `flutter run`、不启模拟器、不 `adb install`。真机验证由用户自己做。
2. **禁止 `dart format`**：仓库是旧版格式化风格，改动风格必须与所在文件现状一致。
3. **禁止提交与推送**：不 `git commit`、不 `git push`、不 force push。用户说"提交"才提交。
4. **禁止改 `pubspec.yaml` 的 `version:`**（本轮固定 `1.3.6+4`）。
5. **禁止改业务逻辑**：本轮只允许改"语言相关"代码（locale 值、语言名、长文分发、测试）。任何功能行为变化都必须先问。
6. **禁止翻译"不可翻译清单"**里的中文（清单 = `docs/archive/i18n-migration-plan/tools/whitelist.json`，逐条写了原因）。典型：字幕简繁识别关键词、弹幕匹配键、写盘文件名兜底、崩溃日志正文、截图相册名、B 站角标匹配键。
7. **禁止用 PowerShell 文本命令改 UTF-8 源码**（`Get-Content` / `Set-Content` / `-replace`），一律用编辑工具。
8. **禁止重排枚举顺序 / 改枚举名**（老存档按 index 持久化）。
9. **禁止改日志语言**：日志、崩溃报告文件内容永远保持中文。
10. **禁止改截图文件名与相册名**（`小喵Player-yyyy-MM-dd_HH-mm-ss`）。
11. **一阶段一收口**：阶段门禁全绿后停下等用户确认，不许连做两个阶段。
12. **不许糊弄**：不许降级实现、不许跳过门禁、不许把没做的说成做了。做不到就说做不到。

---

## 2. 工作循环

```
读本阶段 md（+ 需要时读 02-technical-solution.md 对应小节）
  → 改一小批（一个文件 / 一批 <= 100 个 ARB 键）
  → 跑该批次的自检门禁（G1–G6 里相关的）
  → 通过 → 进入下一小批
  → 不通过 → 修到通过；连续 3 次修不好 → 停下来报告
阶段内全部做完 → 跑本阶段全部门禁 → 在阶段 md 里记录结果 → 停下来等用户确认
```

**改动前先确认工作区干净**（`git status --porcelain` 无输出），这样用户能用 `git diff` 审出你做的每一处改动。

## 3. 门禁 G1–G6

| 编号 | 门禁 | 命令（工作目录 = 工程根） | 期望 |
|---|---|---|---|
| **G1** | 静态分析 | `D:\allexe\flutter\bin\flutter.bat analyze` | 输出 `No issues found!` |
| **G2** | 全量测试 | `D:\allexe\flutter\bin\flutter.bat test` | `All tests passed!`，且通过数 ≥ 1834 |
| **G3** | ARB 硬门禁 | `py "docs\archive\i18n-zh-hant\tools\arb_hant.py" check` | `CHECK PASS`、`hard errors : 0`、exit 0 |
| **G4** | 未翻译清单 | 读 `l10n_untranslated.json` | 内容为 `{}` |
| **G5** | 残留中文门禁 | `py "docs\archive\i18n-migration-plan\tools\i18n_scan.py" residual --include-android` | `residual: 0  expired whitelist: 0` |
| **G6** | 真机走查 | 见 `09-stage7-device-walkthrough.md` | 用例全部有结论（用户执行） |

阶段与门禁的对应：

| 阶段 | 必跑门禁 |
|---|---|
| 1 定调与术语表 | 无（纯文档产出） |
| 2 ARB 译文 | G3；阶段内每批用 `status` 看进度 |
| 3 长文正文 | 自检脚本（段数/小节数比对，见阶段 3） |
| 4 代码接入与生成物 | G1 |
| 5 门禁登记与 Android | G4、G5 |
| 6 测试补齐 | G1、G2、G3、G4、G5（全量复跑） |
| 7 真机走查 | G6 + 最终 G1/G2/G3/G4/G5 复跑 |

> `flutter` 把进度写到 stderr，PowerShell 里偶尔会显示 `[exit code: 1]` 这种假失败；**以输出里的 `No issues found!` / `All tests passed!` 为准**，不要被退出码骗了。

## 4. 必须停下来提问的情况

1. 术语表里查不到、且按台湾习惯译会**改变功能含义或牵扯产品名/法律条款**的词。
   （纯用词偏好**不用问**：按术语表与台湾常用译法定稿，写进阶段报告即可。）
2. 发现 `02-technical-solution.md` 描述的机制与 `flutter gen-l10n` 实际行为不一致。
3. ARB 里出现"看起来该翻但按清单不该翻"的键（可能清单过期）。
4. 门禁连续 3 次修不过。
5. 需要改业务逻辑、需要动 `version`、需要改 Android 原生代码、需要新增依赖。
6. 用户已拍板结论（README §2）与现实冲突（例如用户改主意说要港台两套）。
7. 长文里发现条款本身有歧义/自相矛盾（不要自己"顺手改好"）。
8. 测试红了但看上去是既有问题（第一轮遗留）——**不要顺手修**，报告出来让用户决定。

提问要**一次问清**，不要一条一条挤牙膏。

## 5. 阶段报告模板（收口时用，中文、越短越好）

```
阶段 N · <名字> —— 收口报告

改动：
- <文件路径>：<一句话改了什么>
（按文件列全，别写"若干文件"）

门禁：
- G1 analyze：No issues found
- G3 arb check：CHECK PASS，hard errors 0，疑似未转换 0
- （只列本阶段该跑的）

没做 / 没验到的：
- <如实写；没有就写"无">

下一步等你确认。
```

不许在报告里写"应该没问题""理论上"这类糊弄话；没验就写没验。

## 6. 进度维护

- 各阶段 md 里有 `- [ ]` 勾选清单：做完一项就改成 `- [x]`，并在文件末尾"执行记录"里写日期与结果。
- **不要在两处重复维护同一状态**：阶段 md 是唯一进度源，README 不改进度。
- 报告与证据（截图、日志）放在 `docs\archive\i18n-zh-hant\_evidence\stageN\` 下（目录自己建）。

---

## 7. 命名与风格

- 注释、文档、提交信息一律**中文**，风格跟随所在文件（`///` 文档注释写"为什么"，不写"是什么"）。
- 新增代码里的标识符用英文；日志文案保持中文。
- 代码风格与所在文件一致：本仓库用旧版 `dart format` 风格（**不要跑 formatter**）。
